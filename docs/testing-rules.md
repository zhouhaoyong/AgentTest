# 测试规则

## 人工审核 Gate

生成 `test-points/test-points.md` 后必须停止。正式测试需要用户明确批准。“继续分析”或“看看”不算批准。

## 测试覆盖

对于相关需求，测试以下内容：

- 功能：正常、边界、非法输入、校验、错误、状态、持久化和结果。
- 业务流：前置条件、主流程、分支、失败路径、跨页面 / 跨模块衔接、中断和后置结果。
- 权限：可见性、操作可用性、数据范围、角色隔离、受限访问和越权风险。

记录未覆盖或被阻塞的维度。多步骤或多角色需求不能用单页检查代表完整测试。

## 浏览器与登录

优先使用 Agent 内置浏览器，否则使用 Python Playwright。`BrowserSession` 默认使用 headed 模式。登录由用户手动完成，凭据不保存、不自动填写。不同账号或角色使用独立 Browser Context / Session。

## 范围与安全

只执行已批准的测试点，不自动扩大范围，不删除或覆盖资产；未经用户明确指令不执行 Git 命令。
