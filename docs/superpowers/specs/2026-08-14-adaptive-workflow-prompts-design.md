# 自适应探索与 Prompt 收敛设计

## 目标

让 AgentTest 根据当前需求与既有 System 知识，决定是否需要探索；以用户明确授权和当前 Version 的测试点文件作为正式测试依据；让 Prompt 的职责清晰且没有重复模板。

## 约束

- 不新增 Agent Runtime、服务、数据库或额外命令行入口。
- Markdown 与 YAML 继续是唯一事实来源。
- 用户明确表示可以开始测试时，才可进入正式测试。
- 正式测试、回归测试、登录与敏感信息规则继续以 `AGENTS.md` 为准。
- 回归测试只覆盖当前 Version，不引入跨 Version 或跨 System 回归。

## 自适应探索

需求整理完成后，Agent 先读取当前 System 的 Memory 与 Element Map 索引，并作出探索决策：

- **复用已有知识**：相关模块、流程与定位信息已覆盖；本次需求没有改变这些信息；不存在影响测试设计的关键未知项。此时直接设计测试点，不启动浏览器。
- **目标探索**：只缺少本次需求涉及的一部分模块、流程或定位信息。只探索缺失部分，不执行正式测试。
- **必须探索**：没有可复用的相关知识、已有知识与需求冲突，或关键页面流程、权限、状态和依赖无法据此确定。完成必要探索后再设计测试点。

探索决策不是新增工作流阶段。它是 `requirements` 到 `exploration` 或 `test-points` 的分支；决策、使用的索引和理由应简要写入最终 `test-points.md` 的测试范围，供后续 Agent 接续。

## 测试点授权

用户的明确自然语言授权是唯一授权来源。开始测试前，Agent 必须重新读取当前 Version 的完整 `test-points/test-points.md`，并仅按其中的最终内容执行。

`test-points.md` 不记录 `Draft` 或 `Approved` 状态；每个 Test Point 也不记录此类状态。测试结果只写入 `report/report.md`。`.agentest/state.yaml` 仅记录当前阶段以便跨 Agent 接续，不作为独立的授权凭据；因此删除 `test_points_approved` 字段。

## Prompt 结构

各阶段 Prompt 统一采用以下职责顺序：

1. 进入条件。
2. 必读资料。
3. 决策与执行。
4. 允许写入的位置。
5. 交付物与移交方向。
6. 强制停止条件。

`AGENTS.md` 保留全局安全、资产、登录和 Git 规则；`workflow/README.md` 仅负责路由；阶段 Prompt 只说明本阶段行为；模板只定义最终文件结构。测试点模板仅保留在 `template-test-points.md`，不再嵌入测试点 Prompt。

## 当前 Version 全量回归

在用户确认 Bug 已修复、测试地址与环境可用后，回归阶段重新执行当前 Version 最终 `test-points.md` 中的完整测试点集合。原 Bug 场景必须包含在该集合中；若当前文件未覆盖它，先要求用户更新测试点。报告将本次全量回归单独统计，并保留历史结果作对比。

## 一致性校验

新增静态测试，验证：

- 需求整理 Prompt 通过探索决策分支进入探索或测试点。
- 测试点 Prompt 不再内嵌模板，且模板与示例不含过期的 `Draft` 状态。
- `WorkspaceState` 不再保存独立的测试点批准标记。
- 回归 Prompt 明确执行当前 Version 的完整测试点集合。

这些测试只保护公共脚手架的一致性，不访问业务系统。
# 多系统、数据校对与页面跳转补充

在不改变单系统 Version 主流程的前提下，补充以下约定：

- 需求涉及多个系统时，在 Project 下建立一个“联动范围”，列出参与的系统、版本、地址和操作顺序；各 System 的 Memory 与 Element Map 仍留在原 System 下。
- 涉及统计、指标或数据汇总时，测试点写清口径、时间范围、筛选条件和可参考的数据；测试时在相同条件下比较。没有可参考的数据时标记阻塞，不把页面显示数字直接判为准确。
- 点击后要判断当前页变化、新页面、外部页面还是下载；切到正确位置后再继续。外部页面只验证跳转，下载核对文件名、格式和必要内容。
- 多系统或数据更新有等待过程时，等待可观察结果并写明最长等待时间；成功提示不等于通过，最终要在目标页面或数据中核对。

所有新增 Prompt 保持短句和日常用语，不使用不必要的术语；现有登录、凭据、范围、资产归属和人工批准规则保持不变。
