# requirements 目录契约与结构化需求

## 目录职责

保存本 Version 的原始需求来源和结构化需求。

## 允许内容

- `source.md`：原始文本、链接和附件引用。
- `attachments/`：用户提供的原始文件。
- `requirement.md`：本目录契约和结构化业务需求。

## 文件职责

保留原始来源，不用 Agent 摘要替换原始内容；结构化需求必须使用稳定章节和 `REQ-001` 等 ID。

## 更新规则

不得把未确认的 Project、System、Version、角色或行为写成确定事实。

## 禁止事项

- 不要求 AgentTest 为每种附件格式实现 Parser。
- 不用 Agent 摘要替换原始来源。
- 不保存凭据。

## 阅读策略

生成 Analysis 或 Test Points 前先读 `source.md` 和 `requirement.md`，只在相关且可处理时查看附件。
