# 系统探索 Prompt

你正在理解当前需求涉及的页面、模块、流程和可复用元素；探索不等于正式测试。

## 进入条件

- 用户明确要求探索，或需求整理后的探索决策为“目标探索”或“必须探索”。
- 若结论是“复用已有知识”，不进入本阶段，直接设计测试用例。

## 必读资料

1. 根目录 `AGENTS.md` 和当前 Version 的结构化需求。
2. 相关 System 的 `system.yaml`、`element-map/index.yaml`、`memory/index.md` 及与需求直接相关的模块文件。
   - **加载策略（省 token）**：系统级资产（Element Map / Memory）跨版本复用、按 `index.yaml` 的 `requirement_keywords` / `covers` / `routes` 只加载相关模块，不整包灌入；版本级资产（用例 / 报告）按版本隔离读取。

## 决策与执行

每次探索开始前，先用一句话说明“做什么”，再用一句话说明“为什么”；探索只能补足页面事实，不能替代需求审查。

1. **复用已有知识**的条件是相关模块、流程和定位已覆盖且仍适用；此时记录依据并直接移交测试用例。
2. **目标探索**只查看缺失或可能过期的相关页面、流程、元素和依赖。多个 System 时，只探索各自缺失的部分和交接结果。
3. **必须探索**补足缺失的关键页面流程、权限、状态、依赖或需求冲突证据。
4. 页面探索不能替代需求审查。始终区分业务期望、当前页面实现和无法判断的差异；页面与需求不一致时记录为“页面事实差异”，必要时按编号向用户追问，不擅自改写需求；不创建 PASS、FAIL 或 Bug 结论，不修改业务数据。
5. 全流程统一使用内置隔离浏览器（由 Playwright 驱动系统 Google Chrome 的无痕 / 隔离会话），不再区分"优先 / 其次"两级后端。禁止使用 Edge、Playwright bundled Chromium。启动浏览器前先执行本地环境 pre-flight 检查（操作系统、系统 Chrome、Playwright 可用性）。禁止复用用户当前已打开的浏览器窗口、Tab、Profile 或地址；必须使用新建的隔离 Chrome 会话。无法确认隔离或没有可用 Chrome 能力时，先询问用户是否需要 Agent 协助安装或启用，未确认前不打开浏览器。
6. **只要打开浏览器就开始记录 Element Map**：探索中实际操作过并验证的页面、元素和定位当场沉淀，探索结束即产出第一版 YAML Element Map 供本次测试直接复用，不等到第一次版本测试之后再记。模块必须记录页面、入口、状态、元素用途、主/备用定位、稳定性依据、操作后的状态、验证 Version 和验证视口。定位优先级为测试属性、语义定位、稳定属性 CSS、稳定文本、XPath；账号、UID、动态数量和临时 class 不得作为定位依据。
   - **只定位结构，不烧录数据**：Element Map 只记录页面结构（地标、容器、行模板、控件），用稳定属性定位；具体业务数据（订单号、金额、用户名、数量）靠运行时参数在结构内筛选，绝不把数据值写进 locator。判据是“换一组数据这条定位是否仍成立”——不成立就是把数据当成了结构。
   - **按属性来源判别结构 vs 数据**：前端标记契约（testid、role、aria-label、稳定语义 class）属于结构，可作定位依据；回显的业务内容（文本值、动态计数、状态角标）属于数据，不作主定位；“稳定文本”只在无更好锚点时降权使用。
   - **拿不准的标 `unverified: true`**：只观察到、未实际操作验证的元素，或疑似数据派生的定位，标 `unverified: true` 待复核；这类元素仍须写 id 与用途，但可暂缺 locator，不阻断沉淀。
   - **文案变化不应破坏定位**：优先使用 `data-testid`、语义 role / label 或稳定属性；placeholder 和普通页面文案只能作为备用定位，不能在存在更稳定锚点时作为唯一定位。定位说明要写清为什么换一组业务数据或页面文案后仍然成立。
7. **分离“到达”与“读取”，按成本择优进入目标**：到达某个模块不以读懂整页为前提。优先尝试深链直达（直接导航到目标 URL），并现场校验是否真的落在目标页（比对 URL 或目标页专属锚点）；若被重定向回登录 / 首页，退到用稳定导航文案点击，再退到站内搜索 / 快捷入口。把当次验证成功的到达方式记进 Element Map 的模块入口，不预设固定路由，也不针对单一项目写死路径。

## 探索预算与范围锚定

- **范围锚定是探索第一步（强制产出）**：打开浏览器前，先输出一张「需求点 → 目标模块 → 入口」清单（例如“接单数量上限 → 通讯录/我的订单 → 顶部导航‘通讯录’”），作为本轮探索的收敛锚点。此清单先于任何页面操作产出，不设人工确认闸门，但后续每一步都对照它判断是否偏航。
- **模块粒度**：锚定到导航入口 / 独立页面粒度——一个上方或侧边导航入口、一个独立页面即一个模块；其下的子 Tab、弹窗、列表、抽屉作为该模块的 `pages` / `states` 记录，不再下切成新的模块。
- **无关模块也结构化记录，只是不主动深挖**：凡实际探到或路过的页面/模块，一律用同一套模块模板**完整记录**（同样的 id、入口、页面、元素、定位字段，格式不打折）；范围纪律体现在“不主动绕路深挖清单外模块”，而非“无关就少记或不记”。这样偶遇的可复用事实不会流失，后续版本可直接接着用。
- **探索会话与重试预算**：每个目标模块创建一个 ExplorationSession；进入入口和每次导航都登记成功或失败。会话返回入口重试耗尽时立即改走到达降级链或停下反问，不反复硬试。
- **无进展与总量兜底**：同一 ExplorationSession 记录新增已验证事实和总步数；连续无进展或达到总量上限时停止本模块。墙钟超时仍由运行 Agent 的调度层负责。
- **批量定位验证**：同一会话内批量验证候选定位，让会话使用同一预算和稳定性排序；不得为每个候选重新创建探测脚本或新浏览器会话。
- **触发即止损**：会话返回任一止损原因、或读取 / 导航连续超时时，主动提出“疑似反调试 / devtools 检测或环境阻塞”的判断并停下反问，先把已确认的稳定事实沉淀，不擅自绕过、不继续空耗 token。

## 允许写入的位置

- 仅写入对应 System 的 `element-map/`、`memory/` 及其索引；不复制到 Version 。Element Map 的 YAML 是事实源，Markdown 仅作可选人工索引。
- 不记录完整 DOM、临时日志、推理过程、凭据、账号、UID 或一次性会话信息。
- Memory 模块中的每条事实必须注明“验证 Version”“长期用途”和“稳定事实”；一次性测试结果、Bug 结论、临时网络错误或截图失败只写入报告。

## 交付物与移交方向

- 记录实际采用的探索策略、参考的模块和新确认的长期信息。
- 移交 `test-cases/`；测试用例范围必须简要写明“复用已有知识”“目标探索”或“必须探索”及依据。

## 强制停止条件

- 遇到登录立即暂停，由用户手动完成并明确确认后再继续。
- 无法确认浏览器隔离、需求目标或页面事实时立即停止并按编号提问。
- 用户只要求探索时，在本阶段结束；不得自行进入正式测试或扩大探索范围。
