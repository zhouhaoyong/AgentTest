# Memory 目录契约

## 目录职责

保存未来 Version 测试仍然有价值的长期 System 知识，帮助不同 Agent 接续工作。

## 允许内容

- `index.md`：简短模块索引。
- `modules/`：模块级 Markdown 文件。
- 本文件：目录契约。

## 文件职责

模块文件记录稳定业务规则、角色和权限关系、测试前置条件、数据依赖、系统行为、模块关系、验证过的规律和长期测试经验。

每个模块使用 `template-memory-module.md` 的章节结构；每条沉淀事实都应说明：

- 验证 Version：最后一次验证该事实的 Version。
- 长期用途：未来版本为什么仍可能复用它。
- 稳定事实：经过页面或业务证据确认的内容。

## 更新规则

只写长期可复用知识，并使用小写连字符命名模块文件，例如 `permission.md`。

## 禁止事项

- 不记录一次性聊天、临时推理或 Session 日志。
- 不记录登录账号、UID、密码、Token、Cookie、验证码或 Storage State。
- 不记录一次性测试结果、Bug 结论、临时网络错误或截图失败；这些内容只进入测试报告。
- 不把 Version 需求复制到 Memory。
- 不默认加载所有模块。

## 阅读策略

先读 `index.md`，确定相关模块后，再读取对应模块文件。
