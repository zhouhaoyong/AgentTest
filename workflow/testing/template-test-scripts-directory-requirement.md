# test-scripts 目录契约

## 目录职责

保存本 Version 或联动范围可重复执行的测试脚本。

## 允许内容

- 按测试用例组织的 Python Playwright 脚本。
- 本文件：目录契约。

## 文件职责

每个测试脚本应关联一个或多个稳定的 Test Case ID，并说明必要的前置条件、手动登录方式、执行命令和结果判断。脚本至少应支持当前范围内的重复测试，并用于正式测试和 Bug 修复后的当前范围全量回归；已确认需求发生变化时，应及时调整脚本。所有脚本使用 Google Chrome。相关测试用例应按测试组级 Session 组织：普通导航复用主 Page，业务明确打开新页签时才创建辅助 Page，并在使用后校验和关闭辅助 Page。

## 更新规则

测试用例获批且用户明确要求开始正式测试后，必须先批量创建或调整脚本骨架，再按页面 / 业务流程分组调试定位器和前置数据。正式执行时同组测试用例复用同一个隔离浏览器会话，以测试用例为结果检查点，并显式区分主 Page 与辅助 Page。测试结束前实际运行脚本并记录命令和结果；BrowserSession 退出时自动关闭所有资源。Bug 修复后复用相关脚本并执行当前范围的完整测试用例集合；脚本行为变化时同步更新测试用例或报告说明。

## 禁止事项

- 不保存密码、Token、Cookie 或其他凭据。
- 不保存 Storage State；脚本、日志、截图、Trace、HAR 和视频中也不得出现敏感信息。
- 普通业务数据的 Bug 证据不要求脱敏，不得为了脱敏而影响问题判断。
- 遇到登录必须暂停，等待用户手动输入账号密码并明确确认完成。
- 不把临时探索代码当成正式测试脚本。
- 不自动扩大脚本覆盖范围。

## 阅读策略

先读已批准的 `test-cases/test-cases.md`，再按需读取相关脚本。
