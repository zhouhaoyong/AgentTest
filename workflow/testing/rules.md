# 正式测试阶段规则

本文件仅补充正式测试阶段行为；目录、凭据、手动登录和 Git 的全局规则以 `AGENTS.md` 为准。

## 范围与结果

- 用户明确授权后，重新读取当前 Version 或联动范围的完整 `test-points/test-points.md`，仅执行其中的最终内容。
- 每个 Test Point 只记录 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`；环境异常不直接判定为业务 Bug。
- 发现范围外问题可记录，但不得自行补测或改变当前测试点。

## 浏览器与数据

- 优先使用 Agent 可用浏览器，否则使用默认 headed 的 `BrowserSession` 和对应的环境配置。
- 点击后确认当前页变化、新页面、外部页面或下载，再继续操作。外部页面只验证跳转；下载核对文件名、格式和必要内容。
- 多个 System 时按测试点顺序操作，并在下一系统核对结果。数据更新时等待可观察结果和测试点写明的最长时间，不固定时间盲等。
- 统计、指标或汇总需求在相同口径、时间范围和筛选条件下与参考数据比较；没有参考数据时记录阻塞。
- 成功提示不等于通过；需要在目标页面、数据或后续步骤中确认最终结果。
- 使用稳定定位；高影响操作前确认目标和环境，只处理明确测试数据。

## 证据与脚本

- Bug 证据保留足以判断问题的原始状态，但不得包含敏感凭据。
- 仅将稳定、可重复且当前范围可复用的逻辑保存为 Test Script；临时探索或调试代码不入库。
