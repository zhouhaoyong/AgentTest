# 正式测试 Prompt

你正在执行 AgentTest 的正式测试阶段。

## 前置检查

开始前先阅读：

1. 根目录 `AGENTS.md`。
2. 当前 Version 的 `version.yaml` 和 `test-points/requirement.md`。
3. `requirements/requirement.md` 目录契约及当前结构化需求文档。
4. 已批准的 `test-points/test-points.md`。
5. 当前 System 的 `system.yaml`，以及相关 Test Scripts、System Memory、Element Map 和测试环境配置。

开始测试前必须确认：

- Test Points 已得到用户明确批准。
- 测试地址、System、Version 和环境配置正确且可用。
- 测试地址不是生产环境或其他未经确认的 System / Version。
- 当前测试范围不超出已批准的 Test Points。

无法确认测试地址、环境或测试范围时，先暂停并向用户确认。

## 浏览器执行

1. 优先使用当前 Agent 可用的浏览器，否则使用 Python Playwright。
2. Python Playwright 默认使用 headed 模式，并使用 System 默认环境和 Version 覆盖配置。
3. 页面跳转、新开页签、新窗口或弹窗后，必须确认 URL 或页面标识，并切换到正确页面后再操作；禁止默认当前活动页签就是目标页。
4. 操作前确认页面已达到可交互状态。对于异步加载、提交、刷新、状态更新等场景，应等待明确的页面状态或业务结果，不依赖固定时间盲等。
5. 元素定位遵循 `AGENTS.md` 的定位优先级；避免依赖动态 class、深层 DOM 路径、坐标或临时 locator。
6. 遇到浏览器异常、页面崩溃、登录态失效或环境异常时，不得将其直接判定为业务 Bug，应先区分环境问题和产品问题。

## 测试执行

1. 严格按照已批准的 Test Point 执行。
2. 每个 Test Point 记录 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`。
3. 一个测试点失败后，可继续执行与其无依赖的后续测试点；不得因单点失败无理由中止全部测试。
4. 按已批准的测试点执行功能、业务流程、角色 / 权限、数据范围、数据隔离和越权风险验证；未被测试点覆盖的内容只记录为未测试，不得自行补充执行。
5. 发现批准范围外的问题可以记录，但不得擅自扩大正式测试范围。
6. 不得因为 Element Map 中存在某个页面、元素或操作入口，就推断该行为符合需求。

测试结果判定：

- 业务实际结果不符合已确认的预期结果：记录为 `FAIL`，并按 Bug 规则记录。
- 因登录、浏览器、网络或其他环境问题无法判断业务结果：记录为 `BLOCKED` 或 `NOT RUN`，说明具体原因。
- 环境异常不能直接记录为业务 Bug。

## 测试数据

1. 优先使用专用或可识别的测试数据。
2. 避免修改、删除或污染非测试数据。
3. 测试产生的数据可能影响后续 Test Point 时，应明确记录并按需要清理或复用。
4. 可清理明确创建的测试数据；删除、批量修改等高影响操作必须确认目标和环境，未经用户许可不能处理非测试数据。
5. 涉及删除、提交、审批、批量操作等高影响操作时，应确认目标数据和当前环境后再执行。
6. 不得为了使测试通过而擅自修改需求、环境配置或业务数据。

## Bug 记录

发现 Bug 时至少记录：

- 关联 Test Point
- 测试维度
- 前置条件
- 复现步骤
- 实际结果
- 预期结果
- 必要的截图或其他证据
- 阻塞范围或影响

无法稳定复现的问题应明确标记，不得直接描述为确定性 Bug。

截图和日志是问题证据，应保留足以判断问题的原始状态，不因脱敏而裁剪、遮挡或修改。账号、密码、Token、Cookie、Storage State、验证码及其他敏感凭据不得被记录；登录凭据输入过程不得截图或写入日志。如果证据不可避免会包含敏感凭据，则不要保存该证据，改用文字描述问题。

## 登录与敏感信息

遇到需要输入账号、密码或其他敏感凭据的登录步骤时必须暂停，由用户手动完成。

只有用户明确确认登录完成后才能继续。

禁止自动填写、保存或输出：

- 账号密码
- Token
- Cookie
- Storage State
- 验证码
- 其他敏感信息

敏感信息不得进入：

- Test Scripts
- Report
- 日志
- 截图
- Trace
- HAR
- 视频

## Test Scripts

1. 优先复用当前 Version 已有 Test Scripts。
2. Test Scripts 至少应支持当前 Version 内的重复测试，并可根据已确认的需求变更及时调整。
3. 仅保存稳定、可重复执行且服务当前 Version 或具备明确复用价值的测试逻辑。
4. 临时探索、一次性调试代码不得保留为正式 Test Script。
5. 脚本不得依赖本次会话中的临时状态、敏感凭据或不稳定定位方式。
6. 测试脚本行为发生变化时，同步更新关联的 Test Point 或 Report 说明。

## 测试结束

测试完成后：

1. 复用或补充当前 Version 的 `test-scripts/`。
2. 按 [`workflow/reporting/prompt.md`](../reporting/prompt.md) 更新唯一的 `report/report.md`。
3. 只有长期可复用的知识才更新 System Memory。
4. Element Map 仅按本地资产规则更新，不得将未经验证的推断写入。
5. 向用户汇报：
   - 测试总结果
   - `PASS` / `FAIL` / `BLOCKED` / `NOT RUN` 分布
   - Bug
   - 未测试内容及原因
   - 阻塞项
   - 风险
   - 后续建议

测试完成后不得自行扩大测试范围或继续执行新的测试任务，除非用户明确要求。
