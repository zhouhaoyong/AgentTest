# 正式测试 Prompt

你正在执行当前 Version 或联动范围已获用户明确授权的正式测试。

## 进入条件

- 用户明确表示可以开始测试或按当前测试点执行。
- 当前 Project、相关 System、Version 或联动范围、测试地址与环境可用，且不是未经确认的生产环境。

## 必读资料

1. 根目录 `AGENTS.md`、当前 Version 或联动范围的配置、`requirements/` 和 `test-points/requirement.md`。
2. 当前范围最终的完整 `test-points/test-points.md`；它是本次唯一测试范围。
3. 相关 System 的 `system.yaml`、Test Scripts、Memory、Element Map 和环境配置。
4. [`rules.md`](rules.md)。

## 决策与执行

1. 重新读取当前测试点文件；仅执行其中内容，不依据旧会话、旧状态或过去的测试点版本推断范围。
2. 优先使用当前 Agent 可用浏览器，否则使用 headed Python Playwright。点击后确认是当前页变化、新页面、外部页面还是下载；切到正确位置后再继续。外部页面只验证跳转，下载核对文件名、格式和必要内容。
3. 每个 Test Point 记录 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`。环境、登录或网络异常应记录为 `BLOCKED` / `NOT RUN`，不能直接判定为业务 Bug。
4. Bug 必须关联测试点，记录前置条件、复现步骤、实际结果、预期结果、影响和必要且不含凭据的证据。
5. 多个 System 时按测试点顺序操作，并在下一系统核对结果。数据有延迟时等待写明的结果和最长时间，不固定等待几秒；成功提示不等于通过，最终要在目标页面或数据中核对。
6. 统计、指标或汇总需求按测试点写明的口径、时间范围和筛选条件，与参考数据比较；没有参考数据时记录 `BLOCKED`，不把页面数字直接判为准确。
7. 只在批准范围内使用可识别测试数据；删除、批量修改、提交或审批等高影响操作须确认目标和环境。

## 允许写入的位置

- 当前 Version 或联动范围的 `test-scripts/`、`report/report.md` 及当前结构化需求中的测试后实现说明。
- 仅当信息长期可复用且已验证时，更新对应 System 的 Memory 或 Element Map。
- 不回写测试点授权状态，不保存凭据、临时会话或一次性调试脚本。

## 交付物与移交方向

- 测试结束后更新可重复执行脚本和唯一报告，并向用户汇报结果分布、Bug、未测内容、阻塞项、风险和建议。
- 报告整理需求单独移交 `reporting/`；Bug 修复后的回归需求移交 `regression/`。

## 强制停止条件

- 遇到登录立即暂停，由用户手动完成并明确确认。
- 测试完成后不得扩大范围或继续执行新的测试任务，除非用户明确要求。
